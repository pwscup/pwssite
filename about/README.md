# PWS Cup 事例アーカイブ — 運用ガイド

このディレクトリは https://pwscup.github.io/pwssite/about/ で公開されている「PWS Cup 事例アーカイブ」ページのソースです。

## データの正本はスプレッドシート

事例と年度テーマは、スプレッドシート
[[随時更新] PWSCUP関連の記事・ブログ・プレスリリース一覧](https://docs.google.com/spreadsheets/d/1xfBD17rjLFy9ZPg381ghcHnvk1cu1tw_k1Y6EK3krOk/edit)
で管理します。`cases.json` は同期のたびにこの表から作り直されるため、**`cases.json` を直接編集しても次の同期で上書きされます。** 追加・修正はシートで行ってください。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | ページ本体。`cases.json` を fetch して描画する |
| `cases.json` | 事例データ。`scripts/sync_cases.py` がシートから生成する（手で編集しない） |
| `cases.schema.json` | JSON Schema。バリデーションに使用 |
| `README.md` | 本ファイル |

## 事例を追加・編集する手順

1. シートに1行追加する（書きかけのうちは **項番を空欄** にしておく）
2. 仕上がったら **項番** を振る。項番が入った行だけが公開対象になる
3. [Actions](https://github.com/pwscup/pwssite/actions/workflows/sync_cases.yml) で「[手動] 事例アーカイブをシートから同期」を開き、**Run workflow**（Branch: `gh-pages`）を押す
4. 同期が終わるとビルド・デプロイが自動で動き、数分で[テスト環境](https://pwscup.github.io/pwssite/about/)に反映される
5. テスト環境で確認できたら、ほかのページと同じく gh-pages → master をマージすると本番に出る

同期は自動では動きません。シートを直したら、そのつど手順 3 を行ってください。

シートに不備があると同期は止まり、`cases.json` は前回のまま残ります。エラーの内容（何行目の何が問題か）は Actions の実行ログに出ます。

## シートを編集するときの注意

- **1行が1件の記事です。行の中の列はいつも一緒に動かしてください。** 一部の列だけを選んで並べ替えると、受賞やタイプが別の記事に付いてしまいます。表は「テーブル」に変換してあるので、並べ替えは列見出しの ▼ から行ってください
- **記事を見分けるのは URL です。** 項番は並べ替えのたびに振り直してかまいません（重複だけは不可）
- 公開ページは記事分類の年でまとめて表示するので、シートの行の順番は表示に影響しません

## シートの列

| 列 | 必須 | 書き方 |
|---|---|---|
| 項番 | 公開時 | 整数・重複不可。空欄の行は下書きとして無視される。歯抜けや振り直しは問題ない |
| 公開年 | ✓ | 記事・資料が公開された西暦 |
| 記事分類 | ✓ | `PWS Cup 2026` の形。この年で年度ブロックにまとめられる |
| 区分 | ✓ | 細分類（自由記述）。例：公式ページ、企業公式・受賞報告、研究室ニュース |
| 記事タイトル | ✓ | 記事の見出しそのまま |
| 掲載元 | ✓ | 例：PWS公式、NSSOL、明治大学 菊池研究室 |
| URL |  | `http://` か `https://` で始める |
| 受賞 |  | 例：総合優勝、ベストアタック賞。受賞バッジとして表示される |
| タイプ | ✓ | `公式` / `企業` / `大学` / `論文` / `ブログ` / `その他` のいずれか。左のフィルタに使われる |
| 年度テーマ |  | その年のコンテストの一行テーマ。**1年につき1行だけ**（ふつうはその年の Cup ページの行）に書く |
| テーマ補足 |  | 年度テーマの1〜2文の説明。年度テーマと同じ行に書く |

列は見出しの名前で読み取るので、順番を入れ替えても構いません。見出しの名前は変えないでください。

### 公開年と記事分類の違い

- 公開年 = 記事が公開された年、記事分類 = その記事が対象とする PWS Cup の年
- ふつうは同じ。振り返り資料や後年の参加記では異なる（例：2016年公開の「PWS Cup 2015 振り返り」→ 公開年 2016、記事分類 PWS Cup 2015）

### タイプの決め方

- `公式`: PWS 公式サイト・公式資料・PWS Meetup 資料など
- `企業`: 企業の公式ニュース・PR・技術ブログ・受賞報告
- `大学`: 大学・研究室の公式ニュース・受賞報告
- `論文`: 論文・学会発表・研究発表資料
- `ブログ`: 個人ブログ・Qiita・note・SlideShare など個人/コミュニティ寄りの記事
- `その他`: 上のどれにも当てはまらないもの（報道記事、行政・業界団体の資料など）

### 年度テーマ

年度テーマを書いた行の URL が、テーマのリンク先になります。その年の Cup ページ（例：`https://www.iwsec.org/pws/2026/cup26.html`）の行に書いてください。

## ローカルで試す

```bash
# プロジェクトルートで実行
uv run python3 scripts/sync_cases.py                 # シートを取得して cases.json を作り直す
uv run python3 scripts/sync_cases.py --csv sheet.csv # ダウンロード済みの CSV から作る
uv run python3 scripts/validate_cases.py             # cases.json を検証する
```

シートの取得には、シートが「リンクを知っている全員が閲覧可」になっている必要があります。

## バリデーションの仕組み

- `scripts/sync_cases.py`：シートの各行を検査し（項番の重複、記事分類の形、タイプの値、年度テーマの重複など）、エラーが1件でもあれば `cases.json` を書き換えない
- `scripts/validate_cases.py`：`cases.json` を JSON Schema (`cases.schema.json`) で検証し、`no` と年度テーマの `year` の重複を検出する。gh-pages・master への push のたびに `validate-cases` ジョブとして動き、失敗するとデプロイが止まる（`.github/workflows/convert_markdown.yml`）
