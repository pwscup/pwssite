## PWS Cup 2026 概要

### コンテストストーリー
医療データは、病気の原因を解き明かし、多くの人の命を救う研究の宝の山です。しかし患者のプライバシーを守るため、その利用には厳しい制限がかかっています。そこで近年、本物そっくりの人工データ（合成データ）が注目されています。PWS Cup 2026 は、研究に使えるほどリアルで、しかもプライバシーも侵害しない――そんな **有用で安全な合成データ** をつくる技術を、チーム戦で競います。

題材は、**人々の健康診断を10年にわたって追跡し、糖尿病を発病したかどうかを観測した記録(コホートデータ)** です。発病する人の多くは2型糖尿病ですが、そこに1型糖尿病やMODYといったごく少数の珍しいタイプ **(外れ値)** が混じっています。今年最大の挑戦は、**この珍しいタイプの人たちの病気の現れ方（いつ・どのように発病するか）を保ったまま、その人たちのプライバシーも守ること**。数が少ない人ほど、忠実に再現するほど誰なのか特定されやすく、逆に守ろうとして削ったり曖昧にしたりすると、貴重な情報が失われて研究の役に立たなくなります。この難しいジレンマの限界に参加者たちが挑みます。

参加チームは合成データをつくる **スタートアップ企業** になりきり、 **「防御」** と **「攻撃」** を行います。自社クライアントのデータから安全で有用な合成データをつくって研究者に販売する一方、ライバル企業の合成データの弱点を見つけて攻め込み、相手の顧客に告げ口して評判を落とします。守りと攻め、その両方を知り尽くしたチームだけが、本当に安全で役に立つデータを生み出せるのです。

### コンテストの流れ
コンテストは、**防御** → **攻撃** → **採点** の流れで進みます。

1.  防御フェーズ:
 - 各チームは、配布された健康診断の追跡データ (糖尿病の発病を観測したコホートデータ `B_i` ) から、有用性を保ちつつプライバシーを守る合成データ `C_i` を作成する。
 - 希少タイプの患者 (外れ値) を、再現度 (有用性) とプライバシー保護のバランスをとりながら合成する。

2.  攻撃フェーズ:
 - 各チームは、他チームの合成データ `C_i` に対し、メンバーシップ推論攻撃 (MIA) と属性推論攻撃 (AIA) を仕掛け、元データ`B_i`に含まれる個人の情報を推測する。

これらを順に実施した後、出題者が各チームの結果を2つの軸で評価します。

  - 有用性: 元データと合成データから得られる分析結果の近さ（近いほどよい）
    - 一般有用性：分布としての近さ
    - 特定有用性：データ分析をした際の結果の再現度。生存時間解析の係数の一致など
    - 希少有用性：希少タイプの患者群の再現度
    - 妥当性：その他、データとしての妥当性
  - 匿名性: 他チームの攻撃に対する耐性（攻撃が成功しにくいほどよい）

コンテスト期間中に、この一連の流れを2回実施します。1回目を予備戦、2回目を本戦と呼び、両者の評価結果を総合して勝者を決定します。

### チーム構成 (5+2ルール)
各チームは原則5名を上限とします。ただし、学生主体のチームに限り、上限の5名に加えて次の2つの役割を置くことができます。

 - 指導者（助教などを想定）: チームに技術的な指導を行う。
 - 責任者（教授などを想定）: 運営との連絡に責任を持つ。

指導者・責任者は、競技そのものへの直接的な貢献は望ましくありません。指導者・責任者は複数チームで兼務できますが、兼務する場合は氏名・所属を公開します。また、指導者・責任者が別のチームの通常参加者になることはできません。

**見るのは、いま進行中のフェーズに対応する版です。**[Releases](https://github.com/pwscup/pwscup2026-kit/releases) の先頭に `Latest` と付いているものが、その時点の最新版です。

版の名前は `ラウンド-フェーズ-配布日` の形で、**ルールブックの版名と同じ文字列**にしてあります。

| 版の名前 | 対応する時期 |
| --- | --- |
| `orientation-20260730c` | 参加者説明会（2026/07/30）の時点 |
| `prelim-process-20260808` | 予備戦・加工フェーズ（2026/08/09 開始）向け |

- それぞれの Release の説明に、**その版のルールブック PDF** と、**対になる採点用 Docker イメージのタグ**を書いてあります。手元で自己採点するときは、そこに書かれたタグを指定してください（`:latest` は更新のたびに動きます）。

- 過去の版も残ります。「説明会のときはこうだった」を確かめたいときは、一覧から古い Release を開いてください。ダウンロードは Releases の `Source code (zip)` からどうぞ（リポジトリの「Code」→「Download ZIP」は常に最新を指します）。

## <a id="salt"></a>コホート割当の salt コミットメント

どのコホート `B_i` をどのチームに配るかは、ルールブック §3.2 のとおり `SHA-256(チーム名 ∥ salt)` で機械的に決まります。salt そのものは各ラウンドのデータ配布時に参加チームへお知らせしますが、それまでのあいだに事務局が salt を選び直していないことを検証できるよう、salt のハッシュ値（コミットメント）を先に公開します。

| ラウンド | salt のコミットメント (SHA-256) |
| --- | --- |
| 予備戦 | `49c5074a597afc70cc659bff95764bb9724201f5c2a8f0bb1a4615e853eeaecb` |
| 本戦 | `a63de294a02401bd9221e7b28d9574184724f276a2c22b97d558f7f88b2f7187` |

- 上の値は、salt の文字列を UTF-8 で符号化したバイト列（末尾に改行を含みません）の SHA-256 です。
- salt の公表後は、`printf '%s' '公表された salt' | shasum -a 256`（Linux では `sha256sum`）で上表の値と一致することを誰でも確認できます。
- salt は予備戦と本戦で別のものを使います。上の2つの値を今後変更することはありません。

予備戦の salt は、加工フェーズの終了（2026/08/22(土) 9:00）にともない公開します。

| ラウンド | salt |
| --- | --- |
| 予備戦 | `pwscup2026-prelim-640835c70b0c16c5bae356b2` |

`printf '%s' 'pwscup2026-prelim-640835c70b0c16c5bae356b2' | shasum -a 256` が上表のコミットメントと一致することを、どなたでも確認できます。事務局があとから salt を選び直していないことは、これで検証できます。

本戦の salt は、本戦・加工フェーズの終了後に同じ形で公開します。
